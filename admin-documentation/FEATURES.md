# Ask Sunny Features

## Grounded conversational search

Ask Sunny sends visitor questions through WordPress to an installation-scoped backend. Answers can contain formatted response text, relevant content recommendations, and up to three follow-up questions. Recommendation links are restricted to valid HTTP or HTTPS URLs before being displayed.

The chat supports multiple turns. The full chat app restores an existing conversation when possible, and **Start new conversation** clears the current continuity state and begins again. Visitors can retry a failed message without retyping it.

## Visitor chat experiences

Ask Sunny supplies two shortcodes:

| Shortcode | Purpose |
|---|---|
| `[ask_sunny_chat_form]` | A compact question form for a page, post, or shortcode-compatible widget area. It redirects the submitted question to the selected full chat page. |
| `[ask_sunny_chat_app]` | The full multi-turn chat interface with conversation history, recommendations, follow-up prompts, status feedback, and conversation reset. |

The compact form can also show administrator-defined quick starters. If the visitor has a saved conversation, it provides a **Continue previous chat** link. The full app can receive a new question through the `ask_sunny_prompt` query parameter generated by the compact form.

An **Ask Sunny SPA** page template is available for a standalone, theme-light page shell. Administrators may instead use the normal theme template if it better matches the site.

The shortcodes render nothing when Ask Sunny is disabled. The current dashboard does not expose a general enable/disable control, so this state normally remains enabled unless changed through an earlier version or another administrative integration.

## Content sources

### Directorist listings

Directorist listings are a required source. Directory types are discovered automatically and grouped under the **Listings** tab. Eligible published listing information is normalized into a safe, stable form for indexing. Public custom fields can be included, while scripts and private or operational fields are excluded.

Listing updates, publication changes, trashing, restoration, and deletion trigger synchronization when automatic indexing is enabled. Removing an indexed listing from public eligibility queues removal of its backend record without deleting the Directorist listing itself.

### Directorist listing reviews

Approved Directorist reviews appear under **Listing Reviews** and are indexed as separate records with parent-listing context. A missing parent listing is queued before its review. Reviewer email addresses, IP addresses, administrative metadata, and private identity data are not included in review payloads.

### Other WordPress content

Ask Sunny discovers eligible public WordPress post types and lets an administrator enable them under **Settings > Data Sources**. Each enabled post type becomes its own Data Sources tab. Revisions, autosaves, attachments, scripts, private content, and unapproved metadata are excluded.

The indexing layer supports source eligibility filters for public statuses, registered taxonomy terms, and explicitly allowed metadata. The current dashboard exposes post-type enablement and item-table filters; it does not expose every lower-level source-filter option.

## Index management

Ask Sunny supports automatic and manual indexing:

- **Enable Automatic Indexing** synchronizes enabled content when WordPress or Directorist items change.
- **Index All** starts a bounded reindex for the active source.
- **Add to Index** indexes an individual eligible item.
- **Retry** retries an item whose previous indexing operation failed.
- **Delete Index** removes one backend index record.
- **Delete All Index** removes backend records for the active source.

Indexing works in batches of 25 records and can continue through WordPress scheduled work. Jobs are deduplicated, retry transient failures up to five attempts, and preserve stable item identity. Individual rows display the WordPress status, last indexed time, queue status, and available action.

The Data Sources screen provides:

- Search by item text.
- Index-status filtering: all, indexed, not indexed, in queue, or failed.
- WordPress status filtering.
- Directorist directory type, category, and location filters when applicable.
- Counts for all items, indexed items, queued items, and failures.
- Pagination in sets of 25.

Deleting indexed data does not delete the original WordPress post, Directorist listing, or review. Disabling a source or automatic indexing stops future automatic writes but does not by itself erase already indexed backend data.

## Connection management

The initial **Connect Ask Sunny** screen collects:

- The Ask Sunny backend URL.
- The AI provider, currently OpenAI.
- The model, currently GPT 5.4 Mini.
- The AI provider API key.

Provisioning uses the separate `ASK_SUNNY_PROVISIONING_KEY` from server configuration. A successful response stores an installation-scoped key in a non-autoloaded WordPress option and displays only a safe prefix. A malformed or failed provisioning response does not replace an existing working credential.

After connection, the **Connection** tab can test the connection, replace the provider key or model selection, and disconnect the installation. Disconnecting clears the local installation credential and provider metadata; reconnecting is required before chat and backend operations can resume.

## Chat customization

### Chat content

Under **Settings > Chat**, administrators can configure:

- The WordPress page hosting the full chat app.
- Compact-form submit button text.
- Input placeholder text shared by the compact and full chat experiences.
- A quick-starter heading.
- Up to 20 unique quick-starter prompts.

### Chat appearance

Under **Settings > Chat Appearance**, administrators can customize:

- Primary and secondary button colors.
- Chat input background and border colors.
- Brand logo, title, subtitle, fonts, and colors.
- Assistant avatar.
- User-message solid color or gradient and text color.
- Typing and idle status text.
- Chat-body solid color or gradient.
- Container border, radius, and optional shadow.
- Compact-form quick-starter title and chip colors.

Available bundled font choices are Figtree, Dancing Script, and Playfair Display. Images are selected from the WordPress Media Library, with bundled prototype images used as fallbacks.

## Conversation continuity and visitor controls

Logged-in visitors are identified by their WordPress user ID and a valid WordPress REST nonce. Anonymous visitors receive an isolated session identifier. The browser stores only session and conversation identifiers—not the transcript, answers, recommendations, credentials, or REST nonces.

Anonymous requests are rate-limited using short-lived hashed identity data. A message may contain up to 2,000 characters. Pressing Enter sends a message, while Shift+Enter inserts a new line.

## Privacy, safety, and accessibility

- Browser code never receives the installation credential or provisioning key.
- Backend responses are reduced to approved, sanitized fields before display.
- Executable markup and unsafe links are rejected or removed.
- WordPress personal-data export and erasure tools include Ask Sunny continuity metadata when it exists.
- Deactivation preserves settings and index state while clearing scheduled hooks and the reindex lock.
- Uninstall preserves data by default; deletion requires the explicit server-side `ask_sunny_delete_data_on_uninstall` option.
- Chat controls use semantic labels, live status regions, keyboard interaction, focus handling, and reduced-motion-aware styling.

For retention details, see [Privacy and retention](../docs/PRIVACY.md).
